# V2.3 断线续答设计

当前实现先覆盖本地已接收消息，不开启 QQ 离线历史补取。

## 本地恢复范围

OneBot 收到并通过实时权限、群授权、@/引用和长度过滤的消息后，先在 PostgreSQL `inbox_tasks` 落库，再进入进程内队列。模型生成结果和拆分后的出站正文在发送前写入 `outbox_tasks`。Bot 重启后，已生成且尚未发送的答案可以直接复用，不再次调用 DeepSeek；尚未生成的本地待答任务在 OneBot 恢复后重新进入普通路由，并继续使用原事件键去重。

恢复只处理 `source=live` 的本地记录。不会自动重放入群欢迎、协会负责人/管理转接、管理命令或历史来源记录。过期、取消、权限失效和发送结果未知的任务不盲目重发。

## 状态和边界

`received -> ready_to_send -> sending -> sent` 是持久化主路径；发送开始后连接断开仍按 `delivery_uncertain` 处理，不能证明消息未送达。恢复发送前再次检查授权群，单个 outbox part 有独立状态和发送尝试标识。

待答正文受 TTL 约束，默认 2 小时；清理由现有保留任务执行。长期历史、全群消息归档和私聊历史补取不属于本阶段。

## 历史补取

`RECOVERY_HISTORY_ENABLED` 默认 `false`。只有在当前 NapCat/QQ 部署版本完成接口能力探针、分页去重、覆盖率和自然场景验证后，才允许在现有授权群启用受限补取。接口返回成功不等于离线消息完整；无法确认时必须报告 `partial`/`unknown`，不补发欢迎、负责人提醒或管理命令。
